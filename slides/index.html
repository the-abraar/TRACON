The problem

Many agents, many accounts, and no radar

A working day now means several Claude Code profiles on different plans, Antigravity sessions with their own subagents, and a terminal tab for each. Nothing shows them all in one place.

Silent waits

An agent stops on a question or a permission prompt and sits there for an hour because its tab is hidden.

Invisible burn

Tokens burn across five accounts at once, and the first sign of trouble is a rate limit.

Lost structure

A long session with subagents is a wall of transcript; what ran when, and how long it took, is hard to see.

How it works

The Avalokita engine: a read-only observer

1 · WatchTails every Claude Code profile's transcripts (~/.claude*/projects/**/*.jsonl), live-session pid files and Antigravity brain transcripts, through FSEvents plus a 2-second poll
2 · NormalizeTurns Claude Code and Antigravity events into one FlightPacket per session: state, tool in flight, subagents, tokens, burn rate
3 · BroadcastPushes the whole airspace over ws://127.0.0.1:4040/ws on every change; the same snapshot at GET /api/flights
4 · TraceKeeps a bounded execution DAG per flight (last 40 turns, up to 100 tool calls each) at GET /api/trace?flight=<callsign>
Read-onlyNever writes to ~/.claude* or ~/.gemini; scripts/check.sh fails the build if the engine source gains a write call

The metaphor

Sessions are flights, you are the controller

Flight · callsignOne agent session. CL-BIZ-37AA = Claude Code, profile ~/.claude-biz, session id; AGY-37AC = Antigravity
SquawkThe plan behind the account: SQ-20 Pro, SQ-100 Team or Max, SQ-AGY (set with TRACON_TIERS)
StatePREFLIGHT → CRUISING → TOOL (executing) → HOLDING (waiting on you) → LANDED, or ABORTED
EscortsSubagents spawned by a flight, shown as chips on its card and as nodes in its DAG
Burn rateTokens per minute, averaged over 5 minutes, per flight and for the whole fleet

Execution DAG · VIEW DAG

A session's history as a graph

  • Each turn is a column, chained left to right; its tool calls hang below in order.
  • Agent calls and the subagents they spawned are linked, with tokens per subagent.
  • Badges show latency (or running) and tokens per turn. Pan, zoom and the minimap reach older turns.

DAG detail

Zoom in on any step

  • Long sessions stay readable: the DAG opens zoomed on the six most recent nodes.
  • It refreshes whenever the engine sends a new packet for that flight.

Holding alerts

Know the moment an agent needs you

  • A flight waiting on you (a question, a plan approval, or a tool call with no result for 60 s) turns amber and pulses.
  • With ALERTS on: a two-tone chime and a system notification, at most once per flight every 2 minutes.
  • The tab title shows the count, e.g. (1) HOLDING · TRACON ATC, even in a background tab.

Under the hood

Small, local and tested

Packagesnpm workspaces: avalokita-engine (Node, TypeScript), tracon-ui (React, Vite, Tailwind, React Flow), tracon-cli
RuntimesClaude Code (every ~/.claude* profile and CLAUDE_CONFIG_DIR) and Google Antigravity
SettingsTRACON_PORT (4040), TRACON_WINDOW_MIN (30), TRACON_TIERS (plan per profile)
Checksscripts/check.sh: install, two typechecks, stray files, read-only guard, 16 tests, UI build
Tested onOne 30-day sweep: 287 flights, 16,248 DAG nodes, no broken edges; 377 of 379 subagents matched to the call that spawned them
